## Logical holes

| IDs | Meaning |
| --- | --- |
| LI, LM, LR, LP | Left index, middle, ring, pinky |
| RI, RM, RR, RP | Right index, middle, ring, pinky |
| LT, RT | Left and right thumbs underneath |
| SL, SR | Left and right logical subholes |

There are exactly twelve logical fingering holes. The sound-producing voicing hole is excluded. Logical identity and covered/open states live in the pure immutable profile; physical SVG coordinates belong to presentation only.

The FRONT diagram shows eight main holes and two smaller subholes. BACK shows both thumb holes. Both schematic views preserve **player hand order: left on the left, right on the right**; BACK is not a mirrored photograph. Filled = cover, outlined = open, dashed = unavailable. SVG descriptions name every hole and state, and visible Cover/Open text lists logical IDs. The legend and shape fill work without color.

The common Taiwanese arrangement associates subholes with left and right middle fingers. Other instruments differ. SL/SR labels are authoritative logical identities; illustrated placement does not reproduce the owner's drilling pattern. Confirm hand placement against the actual instrument before treating the drawing as physical instruction.

## Unsupported pitches and spelling

Chromatic pitches such as C♯5, E♭5 and F♯5 have no verified fingering in this profile. Pitches outside the mapped range also receive an unavailable state. The written target stays visible, with dashed holes and an explicit explanation rather than invented cross-fingerings or a misleading all-open diagram. Authored music is never automatically transposed.

Lookup uses concert MIDI pitch; labels preserve authored spelling first, then the score's key context. An enharmonic spelling of an already supported concert pitch uses that pitch's existing chart entry without adding a new chromatic mapping. Future owner-verified chromatic entries can be added as profile data without rewriting the visualizer.

## Honest pitch interpretation

The expected note's conventional fingering is primary. A separate compact live suggestion uses only the existing live-reading predicate: capture listening, stable/fresh pitch, age 0–120 ms inclusive. Stale, uncertain, absent and unsupported pitches have no live fingering. Last graded attempts and retained historical pitch never supply live suggestions.

A microphone detects pitch, not physical hole coverage. Breath pressure and manufacturing differences can produce another pitch with the same suggested fingering. This guide cannot serve as grading evidence. Existing acceptance acknowledges pitch/attack only, never correct written duration. Detector, onset grading, tolerance, timing, stream ownership, violin calibration policy v3, recording, scalar JSON, reports/PDF, Run V2 and IndexedDB remain unchanged.

On wide screens the guide shares the right companion column with the violin guide's existing layout; smaller screens stack after playing feedback and notation. Recording/details/export remain below the workspace. Profile assumptions and references start collapsed. At 320px a scoped body-minimum override lets this guide fit even with classic desktop scrollbars.
