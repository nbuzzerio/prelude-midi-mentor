# Optional local performance audio recording — next ticket

Research only, October 9, 2026. No recording is implemented in 2.9.3.

The monophonic capture controller owns the MediaStream privately in `src/lib/audio/monophonic/microphone-capture.ts`. Its public API exposes start/stop, snapshots, generation and resource counts, but no stream. The Piece Practice acoustic hook owns one controller per run. Start obtains a fresh stream; Stop, background/freeze/pagehide, muted/ended tracks, interruption, completion and unmount stop its tracks. There is no current stream-preserving capture pause/resume. Restart Piece replaces the acoustic owner; Restart Measure resets input within the same owner. Recovery starts paused with microphone off. Scalar analysis is independently enabled, temporary and exportable after completion; run evidence/report persistence is separate.

Proposed boundary: a small browser recording controller under `features/piece-practice`, owned by the acoustic run hook. Add a narrowly reviewed capture-ready/capture-ending observer to lend the existing stream with its generation, avoiding a second permission request. Capture retains sole track ownership; recording must never stop tracks or delay grading. Feature errors must leave practice operational. Do not change Run V2, IndexedDB, scalar export or report schemas.

Suggested lifecycle for owner review: explicit default-off opt-in; begin only during practice, excluding preflight. Request recorder stop before capture disposal on pause/interruption/completion; collect the final data/stop events asynchronously without delaying track shutdown or grading. Resume capture creates a separately downloadable segment; never concatenate independent recorder containers as one file. Restart Measure ends the segment and starts another only after the practice boundary; new runs require a new opt-in. Retain finalized segments through completion with local playback/download and a prominent unsaved-audio warning. Require an explicit discard decision before run replacement/exit; browser close protection cannot guarantee recovery. Revoke object URLs and release blobs/listeners on confirmed discard/unmount. Do not upload or persist audio in this ticket.

Feature-detect `MediaRecorder`; probe `isTypeSupported` for `audio/webm;codecs=opus`, `audio/mp4`/AAC and `audio/ogg;codecs=opus`, then consider the browser default. Use the recorder's actual MIME and matching `.webm`, `.m4a`/`.mp4` or `.ogg` extension; reject unknown types rather than label them MP3. Catch construction/start/runtime failures even after a positive probe. WebKit added WebM/Opus in Safari 18.4, so runtime probing is preferable to browser-name assumptions. Sources: [W3C recording specification](https://www.w3.org/TR/mediastream-recording/), [WebKit Safari 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/).

Proposed budget: 64 kbps requested audio bitrate, at most 20 minutes and 16 MiB of retained chunks across segments; finalize at either limit with a visible notice. Twenty minutes at the requested rate is about 9.6 MB, but actual bitrate and event delivery vary. Request roughly one-second chunks; track bytes and monotonic elapsed time independently of chunk cadence, leaving headroom for final data and Blob overhead. No silent eviction; a strict browser heap guarantee is unavailable.

Independent tests: MIME/extension negotiation; one shared permission request; asynchronous final chunk/stop ordering; stale generations; interruption/restart/exit boundaries; unsupported/full-budget/error paths; URL/listener cleanup; recording-off equivalence of grading, reports and scalar exports. Device QA: Chrome/Chromebook/Android, Firefox and Safari/iOS playback/download, background interruption, long takes and memory limits. No MP3 transcoding, waveform editor, audio persistence or sustained-note grading.
